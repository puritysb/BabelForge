# 모델 JSON 응답 오류 분석과 처리 개선

## 확인한 원인과 한계

운영 점검에서 JSON 모드를 요청한 모델 응답에 `json.loads()`를 적용하자
`Extra data`가 발생했다. 첫 JSON 값 뒤에 공백 이외의 데이터가 있었다는
직접 증거다. 당시 응답 원문은 보존되지 않아 뒤에 붙은 내용이 설명문인지,
다른 JSON 값인지까지는 확정할 수 없다. 원래 문맥을 유지하고 JSON만
반환하도록 명확히 한 재요청은 성공했다. HTTP 성공과 JSON 모드 지정만으로
실제 응답의 형식·스키마·판정이 유효하다고 볼 수 없다.

기존 코드에는 별개의 연구·검수 파서가 있었다. 둘 다 첫 `{`부터 마지막
`}`까지 잘라 바깥 내용을 버릴 수 있었고, Python 기본 JSON 파서는 중복 키를
마지막 값으로 덮어썼다. 이는 `correct`와 `keep`이 충돌하는 응답의 일부만
선택하는 위험이 있었다. 연구 단계는 원래 근거 없이 모델에게 잘린 응답을
닫아 달라고 요청하기도 했다. 검수 단계는 JSON 파싱 실패는 재시도했지만,
호출 경계에서 발생하는 빈 응답·출력 잘림 오류는 즉시 전파했다.

## 변경한 동작

- `model_json.py`가 연구·검수·모델 호출 경계의 공통 파서다.
- 하나의 완전한 객체만 허용한다. 전체 코드 펜스, BOM, 완전한 객체 뒤의
  중복 닫는 괄호만 제거한다. 누락된 내용이나 판정을 생성하지 않는다.
- 추가 설명문, 두 번째 답변, 배열 속 객체, 모든 깊이의 중복 키,
  NaN/Infinity 및 숫자 오버플로, 잘못된 유니코드, 불완전한 객체는 거부한다.
- `_chat_json`은 응답을 검증·정규화한다. 형식 실패는 응답 길이와 SHA-256만
  로그에 기록한다. 원문·번역·인증 정보는 진단 로그에 출력하지 않는다.
- 연구는 전체 원래 근거를 유지해 최대 3회 새로 생성한다. 필수 배열과
  서지 연구의 문자열·불리언·신뢰도 타입도 검사한다. 잘린 답변만 받아
  결론을 만들어 내는 별도 모델 복구 호출은 제거했다.
- 의미 검수·용어 검수는 기존 3회 검증 예산 안에서 형식·스키마 오류와
  빈/잘린 모델 응답을 재시도한다. 숨은 형식 재시도 루프를 중첩하지 않는다.
  네트워크 재시도 정책은 별도이며, 영구적인 요청·인증 오류는 즉시 중단한다.
- 이미 검증된 의미 검수 행은 유지하고 미해결 행만 다시 요청한다. 모든
  응답이 실패하면 승인 없이 중단하며, 용어 수정은 독립 의미 승인과 구별한다.
- `keep`에 다른 수정 문구가 동반되면 모순된 판정으로 거부한다.
  `semantic-v6-strict-json`으로 이전 파서에서 생성된 승인 캐시를 무효화한다.

## 검증 범위

회귀 테스트는 추가 데이터·중복 키·복수 답변·비정상 숫자·잘림·잘못된
스키마·불리언 문자열·승인 충돌·부분 승인 보존·재시도 소진·영구 오류
즉시 중단을 다룬다. 실제 네트워크 호출 없이 모의 모델과 HTTP 응답을 사용한다.
완전한 JSON이어도 제공자가 `finish_reason=length`로 표시하면 승인하지 않는다.

최종 리뷰에서 완료 상태가 누락되거나 여러 completion을 반환한 응답도
거부하도록 보강했다. 정상 종료(`finish_reason=stop`)한 단일 응답만 사용한다.

최종 전체 테스트 **254개 통과**(162.082초), 변경 Python 파일 컴파일과
`git diff --check`도 통과했다. 테스트 로그는
`/tmp/babelforge-json-pr-final-tests.log`에 있다.

운영 도서·카탈로그·OPDS는 변경하지 않았다. 기존 발행본은 유지된다. 향후
이 코드로 재검수·재발행할 때에는 새 검수 버전의 독립 승인이 필요하다.
